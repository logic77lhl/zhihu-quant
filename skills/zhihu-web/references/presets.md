# 实体抽取预设

`extract-entities.mjs` 用预设文件定义「抽取什么实体」。**换实体类型不用改代码，写一个 JSON 就行。**

```bash
node extract-entities.mjs <answers.json> --preset books
node extract-entities.mjs <answers.json> --config ./my-company.json
node extract-entities.mjs <answers.json> --preset books --dict my-extra-words.txt
```

## 字段说明

| 字段 | 必需 | 说明 |
|---|---|---|
| `entityLabel` | ✅ | 显示用，如「书」「库名」「公司」 |
| `entityUnit` | | 「条回答」等，tooltip 用 |
| `tagLabel` | | 「来源」「分类」 |
| `countLabel` | ✅ | 「提及回答数」，出现在表头 |
| `minLength` / `maxLength` | | 长度过滤，默认 2 / 40 |
| `rejectChars` | | **正则字符类**，命中即丢弃。填虚词、语气词 |
| `requireChars` | | 反之，**必须**含这些字符之一 |
| `caseSensitive` | | 默认 false |
| `contextGuard` | | `{ near, re }` —— 命中位置前后 `near` 字符内必须匹配 `re`，否则丢弃。用于「书名号命中但作者名不在附近」这类降噪 |
| `rules` | ✅ | `{ tag, re, group?, anchor? }`。`re` 是**字符串形式**的正则（JSON 不能存字面量）。`group` 取捕获组，`anchor` 指定上下文截取锚点 |
| `dictTag` | | 词典层的来源标签 |
| `dict` | | 裸实体词表（一行一个或数组都行） |
| `dictNeedBoundary` | | 默认 true，词典词要求前后有边界，避免「pandas」命中「pandas-profiling」。**边界分左右两侧、各自独立**，见下节的「词典边界」 |
| `dictLeftGuard` | | `"loose"` = 左侧只要求前一个字符不是字母/数字/下划线（**汉字相邻照样命中**）。默认把汉字也算边界内 |
| `dictRightGuard` | | `"loose"` = 右侧同理。默认把汉字也算边界内 |
| `fixtures` | | 抽取规则的**回归测试**，见下节「抽取规则的回归测试」 |
| `noise` | | 直接进噪音表，命中即丢弃 |
| `maxSamples` | | 每个实体最多保留几条溯源，默认 8 |
| `ctxBefore` / `ctxAfter` | | 溯源快照取多少字，默认 50 / 110 |
| `notes` | | 数组。字符串直接进报告口径说明；函数可写 `({answers, entities, extraction}) => '...'`，但 **JSON 无法存函数**，需要动态内容时用 `--config` 指向 .mjs 或手写渲染层 |
| `extraStats` | | `{label, value}`，value 可为数字 |
| `normalize` | | **别名归一**。`{ stripPrefixes: [正则字符串] }` —— 命中即从实体名里剥掉，剥完相同的实体会合并。用于「同一实体有多种写法」的领域（见下节） |

## 别名归一（`normalize`）

**什么时候需要**：同一个实体在回答里有多种写法，不合并就会把票数拆散。

实测 `preset: cpu`（question/650705759，703 条回答）：

```
i5-12400F  /  12400F          ← 同一颗 U
Ryzen 5 7500F  /  7500F       ← 同一颗 U
```

174 个原始写法里，有 **32 个是别的写法的别名**（29 组，账目见下）。
不归一的话 `12400F` 的赞数会被拆成两份，**榜单头部直接错**。

```json
"normalize": {
  "stripPrefixes": [
    "^i[3579][- ]?",
    "^(?:Ryzen|RYZEN|锐龙)\\s*(?:Threadripper\\s*)?[3579]\\s*",
    "^(?:Xeon|至强)\\s*"
  ]
}
```

产物会多出 `normalized` 字段：`{ before, after, groups, groupsDetail }`。
**`groupsDetail` 是逐组的 `{to, members, from[]}`** —— 合并不是静默的，口径可查：

- `to` = 合并后显示的规范名
- `members` = 合并前这一组有**几种原始写法**
- `from` = 组里除显示名以外的写法

**账目必须闭合**，`verify-output.mjs` 会断言：

```
before - after  ===  Σ(members - 1)
```

`groups` 是**合并组数**，不等于减少的实体数（一组 4 个成员会减少 3 个）。
注意 `from` 的长度**不一定**等于 `members - 1`：当组内没有任何成员恰好等于规范名时
（如 `Xeon E5` + `至强E5` → `E5`），`from` 会列出全部成员 —— 所以账目要用 `members` 算，
用 `Σ from.length` 算会误报。

### 显示名怎么取

- **组内多于一个成员 → 用规范名**（剥完前缀的那个）。因为此时「原来怎么写」本身已经有分歧，
  统一成规范名才干净：`Ryzen 5 3600` + `3600` → **`3600`**，`Xeon E5` + `至强E5` → **`E5`**。
- **只有一个成员 → 保留原样**。数据里只有 `i5-14600KF` 时，它就是 `i5-14600KF`，
  不会被改名成 `14600KF` ——「改名」和「合并」是两件事，前者不该顺带发生。
  （实测 108 个单成员实体里有 63 个是这种 `i5-xxxx`，全部保留。）

所以归一后**仍会看到大量 `i5-xxxx` 形式的实体**，那是正常的：它们没有别的写法。

> ⚠️ **这条规则要求「单成员的原始写法本身必须是个合法名字」。** 如果抽取规则的
> 捕获组里混进了裸前缀（`Ryzen 3 3200G` 被抽成 `3 3200G`、`锐龙55600X` 被抽成 `55600X`），
> 单成员组会把这个碎片**原样保留进报告**。实测踩过两次，见下面第 3 条硬性约束。

### 三条硬性约束

1. **只剥前缀，不做型号族合并。** `12700` 与 `12700K` 是两个 SKU，合并它们会把不同产品算成一个。
2. **合并后的计数是「去重后的回答数」（并集），不是把两个计数相加。**
   实测：8 条回答**同时**写了 `i5-12400F` 和 `12400F`（前者本来就含后者作为子串）。
   相加会让 `12400F` 从 16 虚高到 **22**；并集才是 16。
   `extract-entities.mjs` 内部按 `answerId → votes` 存表来保证这一点。
3. **捕获组里不许混进裸前缀。** 规则的 `group: 1` 必须是**完整型号名**。
   实测两个反例（都已修，勿回退）：
   - `([3579]\s?\d{4}...)` 作用在 `Ryzen 3 3200G` 上会捕获 `3 3200G` —— 阶级数字被吞进组里。
     改成把 `[3579]\s?` 放到组外、组只留 `(\d{4}[A-Z]{0,3})`，**匹配范围一字不变**，
     但捕获结果是 `3200G`。
   - 同一个 bug 还会造出**现实中不存在的名字**。实测出处（用旧正则在全量语料里复现过）：
     `AMD Ryzen 55600X` → `55600X`、`AMD Ryzen 95900X` → `95900X` ——
     `Ryzen` 与阶级数字之间没空格，`[3579]` 就吃掉了阶级位。修后二者分别正确并回 `5600X` / `5900X`。
   - 记法：**型号名里不会出现「数字 + 空白」开头**。`verify-output.mjs` 与
     `test-preset-rules.mjs` 都按这条断言，见到 `3 3200G` 这类名字直接 FAIL。

## 词典边界（`dictLeftGuard` / `dictRightGuard`）

词典层默认**两侧都把汉字算作边界内**（汉字紧邻 → 不命中）。但「汉字紧邻」在不同领域的
含金量完全不同，所以要**分领域、分左右**定：

| 预设 | 左侧 | 右侧 | 实测依据 |
|---|---|---|---|
| `cpu` | `loose` | 默认严格 | 左：`还是不如12600KF`、`酷睿i9-12900K` 是中文常态，收紧整片漏。右：`12400元`、`12400够用` 是价格/规格数字，必须挡 |
| `pythonlibs` | `loose` | `loose` | `觉得numpy和pandas确实也很好用`、`这个库就是requests的`、`用flask的开发团队` —— 两侧都是真命中 |
| `books` | 默认严格 | 默认严格 | 词典里有一批**普通词**（`原则` `断裂` `宪法` `商业模式` `科举`），放宽后 `不失原则`、`资金链断裂`、`八二宪法` 立刻被当成 5 本书 |

判断标准：**词典词是不是「独特 token」**。`12600KF`、`pandas` 这种汉字里凑不出来的，
放宽；`原则`、`断裂` 这种本身就是日常用语的，收紧。

实测数字（改完对 4 份历史产物逐字段对账）：
cpu 放宽左侧补回 2 个实体（`i9-12900K`、`i7-12700K`）与 10 处计数；
pythonlibs 两侧放宽后 50 个库计数上升，抽样全是真命中；
books 两份产物**逐字段一致**（保持严格，零影响）。

## 抽取规则的回归测试（`fixtures`）

抽取规则是这套流程里最常改、最容易**静默**出错的一环：改坏了不报错，
只是在报告里变成错的名字。所以坑要写成 fixture：

```json
"fixtures": [
  { "why": "显卡不得进 CPU 榜：XT / XTX 是 Radeon 后缀",
    "text": "显卡选 7800XT 或者 6650XT，7900XTX 就别想了。",
    "expect": [] },
  { "why": "同一回答里两种写法只计一次（并集不是相加）",
    "text": "i5-12400F 就是 12400F，两个写法我都用。",
    "expect": ["12400F"], "counts": { "12400F": 1 } }
]
```

```bash
node test-preset-rules.mjs          # 跑所有声明了 fixtures 的预设
node test-preset-rules.mjs cpu      # 只跑一个
```

一条 fixture = 一条合成回答。断言是**按回答 ID 归属**做的，所以失败信息能指到具体哪条：
「这条回答**实际**抽出了什么」会一起打出来，而且默认 `exact` ——
多抽到一个也报错，不是只检查 `expect` 里有没有。

**它不重实现抽取逻辑**：写合成 `answers-full.json`，调真的 `extract-entities.mjs`，读它的产物。
复刻一份正则来测等于测副本，副本永远是对的。

规则改了就跑一次。`check-docs.mjs` 会检查这个脚本在 `scripts.md` 里有记录，
但**不会**替你跑它 —— 项目里唯一的强制点就是「记得跑」这件事本身，别省。

> ⚠️ 归一只在预设**声明显式**的 `normalize` 时生效。`books` / `pythonlibs` 没有这个字段，
> 行为与旧版逐字段一致（已用 2248 实体做过回归）。

## 写预设的顺序

1. **先看数据再写规则。** 跑一次 `fetch-answers.mjs`，然后

   ```bash
   node -e "const a=require('./q*-answers-full.json');
   console.log(a.map(x=>x.content).join('\n').slice(0,3000))"
   ```

   亲眼看这个领域的文本长什么样，不要凭想象写正则。

2. **先上高精度规则，再考虑词典。** 书名号、代码块、书名格式这类有明确标记的最准。

3. **统计噪声率。** 抽取完看 `extraction.rejectedSample`，如果被拒的里面大半是真实体，说明过滤太狠。

4. **务必人工验证 TOP 20 的溯源上下文。** 榜单头部错了，整份报告就没意义。

5. **每修一个坑，补一条 `fixtures`。** 否则同一条规则下次改动时会悄悄回退（见上节）。

## 已有的坑

- **中文弯引号 `“”` 主要用于强调，不是书名。** 直接当书名抽会引入大量「当下」「中国」这类垃圾。必须配 `rejectChars`。
- **中文顿号、空格是词间分隔符。** 词典里不要写成「万历 十五年」。
- **同一回答内同一实体只计一次。** 一个回答推荐十本书，每本 `count` 各 +1，不重复累加。
- **`contextGuard` 会误伤。** 作者名离书名太远的情况会被丢掉，观察 `contextGuardDropped` 数量，太大就放宽。
- **规则开头的 `\b` 在汉字前面永远不成立。** JS 的 `\w` 只含 ASCII，汉字不是词字符 ——
  所以 `\b` 挡在「锐龙」「至强」「奔腾」这类**汉字起头**的词前面时，位置 0 不匹配、
  前面是汉字/空格/标点也都不匹配。实测 cpu 一个数据集因此漏掉 `锐龙7 8700G`、
  `锐龙 7 9700X`、`锐龙5 7500F` 等 **15 处**（`锐龙` 只在紧跟在字母数字后面时才被抽到）。
  用 `(?<![\w])` 代替：对 ASCII 与 `\b` 等价，但允许汉字在前。
