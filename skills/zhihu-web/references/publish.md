# 发布版报告：把内部汇总页改造成可对外发布的合规版

> 内部版（`render-answers.mjs` → `q<ID>-汇总.html`）是**全量全文库**：673 条回答正文、逐条摘要、
> 可检索、可双向筛选。它的价值在于自查，**它的形态等于镜像站，不能对外发布**。
> 发布版（`render-publish.mjs` → `q<ID>-发布版.html`）只保留「统计 + 结论 + 极短署名引用」。

## 命令

```bash
$SCRIPTS = "$env:USERPROFILE\.config\opencode\skills\zhihu-web\scripts"
node "$SCRIPTS\render-publish.mjs" q<ID>-answers-full.json \
  --contact "你的邮箱或知乎私信" \
  [--author "你的署名"] [--ad] \
  [--quote-chars 140] [--max-quotes 12] \
  [--keep-anon] [--keep-org] [--keep-paid] [--out <file>]

# 发布前：0 FAIL 才能发
node "$SCRIPTS\verify-publish.mjs" q<ID>-发布版.html [--json] [--strict]
```

读取同目录的 `-answers-full.json`（必需）、`-themes.json`、`-books-llm.json`、`-summaries.json`（可选）。
产出两个文件：

| 文件 | 用途 |
|---|---|
| `q<ID>-发布版.html` | 对外发布的报告（无全文） |
| `q<ID>-发布版-citations.json` | 引用清单：逐条引用文本、作者、赞数、原链接、剔除统计——用于自证与撤稿处理 |

`verify-publish.mjs` 默认在报告同目录找源数据，找不到再看当前目录；报告被复制到别处时用 `--source` 指向原数据。

## 五道硬闸门（默认开启，别关）

| # | 闸门 | 实现 | 为什么 |
|---|---|---|---|
| 1 | **不收录任何全文** | 页面不渲染 `content`；只有统计与结论 | 全量复制 = 信息网络传播 + 汇编，且构成对原平台的实质性替代 |
| 2 | **引用一律短引用** | 每条 ≤ `--quote-chars`（默认 140 字）且必须在句读处截断，逐处以「」标注 | 控制"适当引用"的边界；页脚自动披露引用总量与占样本正文的比例 |
| 3 | **剔除敏感与无授权风险内容** | 匿名用户 / 机构号与广告主 / 严选付费内容默认剔除；观点与书单**按保留集重算**，不沿用内部版数字 | 匿名性、商业推广、付费内容三类是投诉高发区；不重算会出现"剔了但数字还是老的" |
| 4 | **署名 + 回链** | 每处引用带作者、赞数、日期、原答链接，并注明「发表于知乎」 | 平台协议对站外转载的署名要求 |
| 5 | **AI 标识 + 免责 + 撤稿通道** | 文首显式声明「AI 辅助生成」＋文件元数据隐式标识；免责声明；`--contact` 写入撤稿通道 | 《人工智能生成合成内容标识办法》（2025-09-01 施行）要求面向公众发布时主动声明 |

引用还会自动过滤：导语/推广语（"小编""点赞收藏""说点题外话"）、营销与联系方式（微信、星球、领取资料）、
书单式与条目式片段（避免整段书目搬运）、人身攻击与名誉风险表述（"混混""骗子""臭名昭著"等）、
以及缺主语的指代开头（"该书…""所以…"）——保证引用是**完整句子且指向明确**。

## 发布前自动闸门（verify-publish.mjs）

```powershell
node "$SCRIPTS\verify-publish.mjs" q<ID>-发布版.html [--json] [--strict]
# 只想知道「有没有 / 过没过期」：node "$SCRIPTS\precheck.mjs" <ID> --publish
```

它复核的是**产物本身**，而不是「生成它的脚本」——模板只能保证按当时的输入渲染，保证不了
生成之后源数据又变过、HTML 被手工改过、引用其实是模型改写的。退出码 0 = 0 FAIL；1 = 有 FAIL。

| 组 | 断言 |
|---|---|
| 产物与来源 | 台账存在；源数据可读；源数据 mtime 不晚于 `generatedAt`（否则数字已过期）；页面 < 1.5 MB（防止把内部汇总页当发布版） |
| 数据口径 | 保留数、匿名/机构/严选三类计数、样本字数、引用占比，全部用与 render-publish **同一套规则**（`publish-rules.mjs`）重算 |
| 引用台账 | 每条引用是原答正文的**逐字子串**（防改写/拼接）；长度 ≤ `--quote-chars + 2`；URL 里的回答 ID 与台账一致；作者不重复；不属于应剔除的三类 |
| 页面结构 | 引用块数 = 台账条数；每块有作者/赞数/日期/回链/「发表于知乎」；引用块之外与任何回答正文不得有 ≥40 字连续重合（20–39 字 WARN） |
| 合规声明 | 可见的「AI 辅助生成」+ `meta name="ai-generated"`；撤稿通道；联系方式不能是占位符；免责；「不收录全文」 |
| 数字自洽 | 文首/页脚写的引用数、字数、占比、样本数、剔除分项，必须与重算一致（手工改数字会当场 FAIL） |
| 软提示 | 攻击性/营销语气引用、快照 >30 天、非知乎外链 |

为什么「逐字子串」这条最值钱：引用抽取是启发式的，人工换句时很容易顺手改两个词；
一旦改写，署名就变成把别人的话安在别人头上——这是比「引用太长」更硬的风险。

`--strict` 把 WARN 也当失败（CI/批量发布用）；`--json` 给自动化读。
闸门自身的回归测试：`node "$SCRIPTS\test-verify-publish.mjs"`（合成数据，10 项断言；改渲染或闸门后必跑）。


## 发布前的人工检查清单（脚本替代不了）

- [ ] **逐条读一遍引用**：抽取是启发式的，可能截出语气不当或脱离语境的句子；不合适就换（改 `--quote-chars` 或直接删该条后重跑）
- [ ] 填好 `--contact`（空占位符不要留着发出去）
- [ ] 若挂带货/推广链接：加 `--ad` 让页面标注"含商品推广（广告）"
- [ ] 不要写"知乎高赞一致推荐"这类背书：用可核验的数字（"N/673 条回答推荐了 X"）
- [ ] 复核平台规则与法条的最新版本后再发（知乎协议、反不正当竞争法关于数据抓取的规定会更新）
- [ ] 想转载全文的，走"联系原作者单独授权"这条路，别用抓取件冒充授权件

## 已知局限

- **引用抽取是启发式的**：只保证"短、完整句、有署名"，不保证"最能代表该回答"——所以第 1 条人工检查不能省
- **书单是词典法**：召回是小众书目的下限，只覆盖主流书目；不使用纯模型抽取（实测会编造书名）
- **"热度"是代理指标**：Σlog10(1+赞)，不等于书或观点的真实价值；早期回答天然占优
- **数据是快照**：赞数持续变化；与平台显示总数的差额（已删除/折叠）必须在报告里写明
- **本文件不是法律意见**：规模化收费前请让律师按你的具体形态过一遍
